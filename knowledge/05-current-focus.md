# 当前主线

最后更新：2026-05-30

## 当前阶段

Sub2API 近期稳定主线已经再次前移。教程 CMS、登录后跳转保持和共享额度窗口仍然成立，但它们已经不再代表最近几天最值得优先续做的默认心智；当前更靠近主线的是“chat image workspace migration + 嵌入式登录会话恢复 + 模型目录/定价同步”。

## 当前重点

1. chat image workspace migration 已成为更靠近用户入口的高频主线
   - 最近大批量改动已经把重点推进到 `/chat-images`、`/canvas`、OpenWebUI launch 以及嵌入式工作区体验，而不是停留在教程页或共享展示本身。
   - 这条线会同时碰到前端用户入口、后端 launch token/redeem、图片任务、模型白名单、计费映射和公共页导航，不适合只按单文件理解。

2. 嵌入式登录态恢复已经成为稳定约束
   - 近 2026-05-29 至 2026-05-30 的修复重点之一，是让 embedded mode 下的会话在 stale token 或 cookie 失配后仍能恢复，而不是简单跳回匿名态。
   - 这意味着后续继续改聊天生图嵌入、Sub2API 跳转或用户会话桥接时，要把 cookie/session/auth store 一起看，不能只看 launch 页。

3. 模型目录与定价同步已进入默认产品面
   - 最近稳定改动已经把 `claude-opus-4.8` 和对应展示/计费口径补进默认目录，说明模型广场、fallback pricing、后端 billing family 和第三方映射已经形成一条固定协作面。
   - 后续遇到“只是补一个模型”的需求时，不应只改前端展示卡片；至少要同步默认模型列表、fallback pricing、映射测试和公开展示顺序。

4. 教程 CMS / 登录跳转 / 共享额度窗口仍是基础层，但不再是最近最高频的续做入口
   - 这些能力已经从“当前主线”退到“稳定背景约束”。
   - 继续补知识时，优先解释当前用户从公共页进入工作区、如何保持登录态、如何使用聊天生图/嵌入入口，而不是重复教程页的初始上线背景。

## 已稳定结论

- `knowledge/tasks/current-task.md` 仍适合记录动态交付快照，但当前更稳定、更常复用的主线已经从“教程入口产品化 + 认证跳转收口 + 共享额度窗口”推进到“聊天生图/嵌入工作区 + 会话恢复 + 模型目录/定价同步”。
- 教程页现在是稳定公共内容链路，不再只是公共前端文案；但如果只看它，会低估最近聊天生图与嵌入工作区改动的影响范围。
- 登录后保留目标跳转仍是默认心智，而且最近又进一步延伸到 embedded session 恢复；后续涉及登录/注册/launch/redeem 和用户页入口时，不应假设“丢 token 后直接重新登录”就是可接受行为。
- `sub2api` 与 `chatgpt2api` 仍需分开维护知识：前者偏 gateway、公共入口、嵌入式工作区桥接、模型/计费目录；后者偏独立图片工作台、`/canvas` 节点工作区和 ChatGPT Web 能力封装。

## 现在不该误判的点

- 不要再把当前仓库默认理解成“教程页 + 容量池展示”的延长线；最近主线已经明确偏向聊天生图工作区、嵌入链路和模型目录同步。
- 不要把 embedded session 修复当成单纯登录页小修；它实际影响嵌入工作区可用性、cookie 恢复语义和用户从 Sub2API 进入工作区后的连续体验。
- 不要把 `claude-opus-4.8` 这类模型补录当成纯展示文案；它通常牵涉 fallback pricing、默认模型、映射和测试。
- 不要只看 `docs/ai/current-task.md`；该文件仍是兼容旧入口的说明，当前事实应以 `knowledge/`、`knowledge/tasks/current-task.md` 和时间轴为主。
- 不要把本地 fake 演示账号或 fallback 教程内容当成正式生产数据；它们仍主要服务本地预览、升级兜底或空态保护。
