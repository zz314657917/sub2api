# 当前主线

最后更新：2026-05-18

## 当前阶段

Sub2API 近期稳定主线已经从“先把聊天生图工作台和双仓库链路打通”，推进到“围绕账号共享、容量池展示、排行榜文案和导入/运维入口做产品收口”。

## 当前重点

1. 账号共享产品化
   - 最近提交已把共享账号从隐含后端能力推进到显式展示能力，前端开始展示 share display account count。
   - 这条线通常会同时触碰后端 DTO、service、前端表单、共享展示卡片和 i18n。

2. 容量池与调度展示收口
   - `/monitor` 容量池当前重点是按套餐聚合展示、隐藏空池、统一剩余百分比文案，并避免 fake 演示账号污染真实调度。
   - 这是“后端查询逻辑 + 前端显示策略 + 测试断言”三者联动的改动面。

3. 排行榜和用户侧文案
   - 排行榜徽章、奖励或展示文案仍在持续细化。
   - 这类改动通常不是孤立的翻译修饰，而是用户侧产品表达和运营规则的一部分。

4. cockpit / 导入与公共页辅助入口
   - 近期提交已补 cockpit import guide，说明公共文档/入口还在继续跟产品主线对齐。
   - 继续补文档时，优先记录“用户怎么进入、看什么、如何判断成功”，而不是只列静态页面路径。

## 已稳定结论

- `knowledge/tasks/current-task.md` 适合记录双仓库聊天生图和 COS 这类动态交付快照，但当前更稳定、更常复用的主线已经转向共享展示和容量池视图。
- 容量池视图不是单纯前端页面；它依赖后端套餐分组、调度过滤、fake 数据隔离和 i18n 文案一起成立。
- `sub2api` 与 `chatgpt2api` 仍需分开维护知识：前者偏 gateway、账号共享、展示和产品入口；后者偏独立生图工作台、white-label 和 ChatGPT Web 能力封装。

## 现在不该误判的点

- 不要把最近的共享展示数、容量池和排行榜改动继续归类成“聊天生图收尾”，它们已经是新的默认产品主线。
- 不要只看 `docs/ai/current-task.md`；该文件已偏旧入口兼容提示，当前事实应以 `knowledge/` 和时间轴为主。
- 不要把本地 fake 演示账号当成正式种子数据或迁移能力；当前仍主要是本地预览辅助数据。
