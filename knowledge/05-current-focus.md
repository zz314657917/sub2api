# 当前主线

最后更新：2026-05-22

## 当前阶段

Sub2API 近期稳定主线已经再次前移：在账号共享、容量池展示和排行榜收口之后，最近两天更靠近默认产品入口的主线已经变成“教程 CMS + 登录后跳转保持 + 共享额度窗口约束”。

## 当前重点

1. 教程页从静态说明升级为产品化内容入口
   - `/tutorial` 已不再只是硬编码公共页，而是后台可编辑的教程 CMS。
   - 这条线同时覆盖 migration、repository/service、公开 API、管理端路由、前台回退内容和 Markdown 渲染约束。

2. 登录与跳转链路收口
   - 最近新增的 redirect preserve 说明登录、注册、邮箱验证和用户侧 launch 入口已经按“先带回原目标页”收口，而不是只做基础认证表单。
   - 这类修改会同时影响 router guard、auth 页面和用户控制台入口，属于高频续做面。

3. 账号共享展示进入“可见额度窗口”阶段
   - share display 已不再只是展示账号数量，最近已经推进到 quota window / usage window 语义。
   - 这意味着共享能力的默认理解应包含后端约束、DTO 字段、表单输入和用户侧展示卡片，而不是只看列表上有几个共享账号。

4. 共享展示、容量池和教程入口已经形成新的用户入口组合
   - 当前公共入口更强调“先看教程、再登录、再进入控制台/共享能力”，不再只是围绕排行榜、容量池或旧导入说明做收尾。
   - 继续补知识时，优先记录用户如何进入、页面如何回退、后台如何发布，而不是只罗列组件文件名。

## 已稳定结论

- `knowledge/tasks/current-task.md` 仍适合记录教程 CMS 这类动态交付快照，但当前更稳定、更常复用的主线已经不是单纯“共享展示 + 容量池”，而是“教程入口产品化 + 认证跳转收口 + 共享额度窗口”。
- 教程页现在是产品数据链路，不再只是公共前端文案；后台发布状态、fallback 默认内容和前台渲染约束要一起理解。
- 登录后保留目标跳转已进入默认心智；后续涉及登录/注册/邮箱验证和用户页入口时，不应假设“登录成功统一回首页”。
- `sub2api` 与 `chatgpt2api` 仍需分开维护知识：前者偏 gateway、教程/控制台入口、共享展示与账号流转；后者偏独立生图工作台、white-label 和 ChatGPT Web 能力封装。

## 现在不该误判的点

- 不要把最近的教程页改动继续当成“公共页视觉优化”；它已经是可后台维护的内容系统。
- 不要把 share display quota window 当成轻微文案修饰；它实际上改变了共享能力的默认约束表达。
- 不要只看 `docs/ai/current-task.md`；该文件仍偏旧入口兼容提示，当前事实应以 `knowledge/` 和时间轴为主。
- 不要把本地 fake 演示账号或 fallback 教程内容当成正式生产数据；它们仍主要服务本地预览、升级兜底或空态保护。
