# Task Contract: leaderboard-participation-exclusion-s70

## Task ID

`leaderboard-participation-exclusion-s70`

## Status

`approved`

## Role

Generator implements a user-level leaderboard participation control after this contract is approved.

## Goal

Allow an administrator to mark a platform user as excluded from the leaderboard. An excluded user remains active and billable, but is omitted from leaderboard ranks, daily champions, badges, and leaderboard reward eligibility.

## Success Criteria

- `users.exclude_from_leaderboard` is a forward-only boolean column with a `false` default, represented in the Ent schema and service user model.
- The admin user GET/list DTO exposes the flag. `PUT /api/v1/admin/users/:id` accepts an optional boolean, preserving the existing value when omitted.
- The existing user edit modal has an accessible `Exclude from leaderboard` checkbox. It always sends the boolean value, including `false`.
- Both user leaderboard query paths exclude marked users before ranks, totals, previous-period movement, and current-user entry are computed:
  - raw `usage_logs` windows;
  - `user_usage_daily_stats` long-window and all-time windows.
- Daily champions and all leaderboard badge leader queries exclude marked users.
- Existing leaderboard reward code remains unmodified and receives no eligible rank/current-user entry for an excluded user, preventing new reward eligibility.
- Updating the flag clears all in-memory leaderboard caches so the next request observes the change.
- General admin usage reporting, API access, billing, balances, subscriptions, and upstream accounts are unchanged.

## Constraints

- This is a platform-user setting, not an upstream account or My Accounts setting.
- Use `exclude_from_leaderboard`; do not overload account status, user status, notes, or a generic blacklist.
- A `false` value is meaningful and must not be discarded by JSON binding or the frontend payload.
- Apply the SQL exclusion before window functions and aggregate totals. Do not filter only final displayed rows.
- Do not add a user-table column in this Sprint. The edit dialog is the maintenance entrypoint.
- Preserve the existing five-minute cache behavior for usage writes; clear caches specifically after an administrator changes the participation flag.
- Do not modify the completed S69 contract or its evidence files.
